# 力矩前馈调查记录

记录日期：2026-11-21。

## 结论与使用约定

**力矩前馈不能统一按“算法力矩除以 4 就得到正确 SDK 指令”处理。** 换算取决于主控固件、SDK 驱动配置、关节系数和协议编码量程。旧接口中的 `/4` 是历史实现，不是已完成真机标定的通用关系。

新接口 `piper/interface/piper_new.py` 只允许固件严格高于 1.8.8。应用层以输出端 N·m 传入 `pyAgxArm.move_mit(t_ff=...)`，由匹配固件的 SDK 实现分轴缩放和编码，不再额外统一 `/4`。当前确认的主控版本 `S-V1.9-1` 使用 `v189` 驱动：其实现按各轴 `c` 系数换算，并采用 ±16、12 位力矩编码。读取 SDK 已换算的 `torque` 后也不重复乘系数。

## 旧固件下发现的现象

在之前 `S-V1.5-8` 的 VMC 零 PD 日志稳定段，给定力矩与电流估算反馈存在明显差别。例如 J3 给定幅值约 1.882 N·m，反馈幅值约 4.230 N·m；J5 给定约 0.719 N·m，反馈约 0.289 N·m。因此不能把所有关节看成同一个固定倍率。

对旧日志套用“SDK 按 ±8 编码、底层按 ±18 解码”的假设，再考虑各轴系数与量化，能较好拟合六轴反馈，包括接近零的 J6 指令对应约 0.057 N·m 的反馈。但这只是数值拟合，**没有证实底层实际使用 ±18，也没有证实应统一再除以 2.25**。

MIT 位置 PD 下未呈现相同倍率；将 `kp=0.5` 的比例项与上述缩放后的前馈叠加，仍无法解释反馈。反馈包含控制器总输出，且电流反馈不一定能提供可靠方向，不能用“反馈幅值减前馈幅值”当作 PD 力矩或有符号跟踪误差。两种状态表现不同的具体根因尚未查实。

新版接口迁移是独立的 SDK 接入变更，不代表旧固件的缩放假设得到证实，也不将旧日志的经验倍率套到新固件上。
